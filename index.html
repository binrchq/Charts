Chart

headcni

Kubernetes CNI：用 WireGuard 组建跨节点 Pod 网络，路由由 Headscale 统一编排。

headcni v1.1.0 Networking

daemon 以 hostNetwork 运行，负责 IPAM、路由与 Headscale 协调； tailscaled 子进程运行在独立 netns 中，通过 veth 与宿主网络栈相连。 因此不需要修改宿主机的 fwmark、路由表号、ip rule 优先级或 iptables 链名。

Architecture

netns 隔离拓扑

两个独立的内核网络栈：宿主 netns 只增加一根 veth、一条 SNAT 和若干明确路由； tailscaled 的路由表、ip rule、fwmark 与 iptables 链全部留在隔离栈内。

host netns宿主机网络栈
tailscale010.2.0.17/32 · 节点身份
cni010.42.5.1/24 · 本机 Pod 网关
hcni0169.254.10.1/30 · 通往隔离区
ip rule 52xx / table 52 / fwmark 0x80000 属于宿主 tailscaled，本方案不做任何改动。
headcni netns/var/run/netns/headcni
hcni1169.254.10.2/30 · 默认路由出口
headcni01tun · WireGuard 数据面
tailscaled:41641 · 官方 v1.104.4
自己的 table 52、52xx 规则、0x80000 与 ts-* 链。数字与宿主相同，但命名空间不同，因此不冲突。
veth pair： hcni0 ↔ hcni1 宿主侧仅一条 MASQUERADE 169.254.10.0/30，用于 tailscaled 自身出网
Pod → Pod
Pod → cni0 → 宿主任路由 10.42.1.0/24 via 169.254.10.2 dev hcni0 → hcni1 → headcni01 → WireGuard → 对端
全程保留 Pod 源 IP，不做 NAT
自身出网
tailscaled → default via 169.254.10.1 → hcni1 → hcni0 → 宿主 eth0 → MASQUERADE
169.254.10.2 是链路本地地址，必须 SNAT 才能收回包
宿主 tailnet
tailscale0 → table 52 → 物理网卡
完全不经过 hcni0，与 CNI 数据面互不干扰
